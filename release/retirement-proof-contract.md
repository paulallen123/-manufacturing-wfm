# Capability retirement evidence

The capability-superset validator permits a `superset-proven` retirement decision only when each entry in `proofRequiredToRetire` has exactly one receipt descriptor in `proofReceipts`. A descriptor contains `proofType`, `evidencePath`, `evidenceSha256`, and `evidenceSignature`. Evidence paths must remain under `release/retirement-evidence/` as regular JSON files. The signature is Ed25519 over the exact evidence-file bytes; a trusted release runner supplies `VECTOR_RETIREMENT_PROOF_PUBLIC_KEY` in PEM form. Missing, malformed, or untrusted signatures deny retirement.

Each evidence file must name the exact `capabilityId` and `proofType`, have `status: "PASS"`, a nonempty `evidenceRef`, the current 40-character source SHA, the exact `sha256:` image digest, and valid `observedAt`/`expiresAt` timestamps. The validator consumes `VECTOR_CANDIDATE_SOURCE_SHA`, `VECTOR_CANDIDATE_IMAGE_DIGEST`, and the current clock. `VECTOR_PROOF_NOW` exists for deterministic isolated tests and must be set by a trusted release runner if used in admission.

The signature establishes authorship only relative to the public key configured by the trusted release runner. The release owner must control signer custody, independently verify proof admission and customer outcome, and rerun the validator against the exact final image before retiring legacy source. A public key supplied by the same untrusted actor who controls the evidence does not establish independence.
