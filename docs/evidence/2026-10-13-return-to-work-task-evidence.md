# Return-to-work exact-task evidence boundary

Source: accepted research/convergence row “return to work task readiness,” issue #265 comment 5971538838. An ended absence, “may be fit,” or active status cannot establish readiness for a specific task. The existing manufacturing scheduling engine checks worker status, availability, skills, certificates and rest; it does not consume task-specific return-to-work restrictions or independent clearance.

This isolated evaluator checks an opaque task/worker/site/assignment-revision binding, full assignment interval, source reference, separate approver reference, and explicit task controls and restriction resolution. It never stores health details and never emits assignment authority. A complete shape remains `EVIDENCE_COMPLETE_UNVERIFIED`; the canonical scheduling owner must bind actual authenticated policy, evidence provenance, current permissions and assignment publication before changing any decision. No real personnel or customer data is used.

The evaluator is deliberately unwired. It cannot make an ended absence into a publishable shift, and its caller-supplied references are not trusted source proof. Canonical integration needs an authority-owned evidence contract and a fresh exact-candidate worker/task/readback/audit journey.
