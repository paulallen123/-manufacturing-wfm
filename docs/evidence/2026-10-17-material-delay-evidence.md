# Material-delay evidence — bounded L8 package

- **Accepted outcome:** expose current, scoped evidence that a declared inbound material supply will arrive after its production requirement, without converting that observation into purchasing, scheduling, machine, savings, causality, or customer-readiness authority.
- **Research reused:** historical PR #75 supplies the delivery-disruption and workflow-handoff-only boundary. This package deliberately does not recreate its event graph, economic ranking, action options, provider adapters, or direct-actuation prohibitions.
- **Ownership:** issue #265 comment `6234433688` reserves only the new source/test/workflow/evidence files. Current code/PR/branch searches found no focused `material-delay-evidence` package. Existing Capacity Rescue, Decision Episode, provider-contract, UI, Dockerfile and canonical-release owners remain untouched.
- **Inputs:** one requirement and one supply observation with exact tenant, site, material, production-order and requirement-revision identity; canonical UTC instants; finite positive quantities; matching units; explicit active lifecycle; independent opaque source references; bounded evidence age.
- **Output:** immutable `DELAY_EVIDENCE_CURRENT`, `ON_TIME_EVIDENCE_CURRENT`, or `BLOCKED` receipt. Successful receipts expose the exact scope, timestamps, quantities, units and source references while declaring `sourceAuthenticated:false` and all action/customer authority false.
- **Failure cases:** malformed/active JSON, scope/revision drift, impossible or future observation time, stale evidence, inactive supply, insufficient quantity, unit mismatch, missing source references and coercive numeric input fail closed.
- **TDD evidence:** before the module existed, `node --test operations/runtime/material-delay-evidence.test.cjs` failed with `MODULE_NOT_FOUND`. The initial implementation reached 8/8. Independent review then reproduced mutable-primordial and primitive-prototype failures; the two added regressions failed 8 pass/2 fail before repair and passed 10/10 after repair. Re-review found constructor replacement could redefine accepted prototypes; the exact added regression failed 10 pass/1 fail before capturing the original prototypes and passed 11/11 after repair. Source and test syntax checks pass on Node v24.19.0.
- **Independent review:** final exact local bytes have 0 Critical, 0 Important and 0 Minor findings. The reviewer executed the committed 11/11 plus two held-out groups totalling 14/14, covering chronology/freshness boundaries, all five identity dimensions, coercive/non-finite quantities, proxy traps, detachment/deep freezing, authority denials, mutable primordials and post-import global `Object`/`Array` replacement. Total behavioral checks: 25/25.
- **Truth boundary:** source references are consistency identifiers, not authenticated ERP/EDI custody. Delay is a timestamp difference, not proof of cause, production loss, avoided cost or realised savings. No route, connector, consumer, writer, workflow action or runtime installation is included.
- **Remaining proof:** supported Node 22.23.2 source and repository regression; unchanged Docker build; canonical-owner reconciliation; explicit provider/consumer integration; authenticated hosted durable-state/fresh-login/downstream/audit proof.
