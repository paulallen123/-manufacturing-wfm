# 24-Hour Category-Leader Sprint

## Mission
Deliver the maximum credible integrated version of the product within 24 hours, focused on the capabilities that make CADDi, Tulip, MaintainX and leading WFM platforms stronger today.

This is an execution sprint, not a promise to fabricate maturity. Anything not genuinely proven remains labelled unproven.

## Operating rule
When a requirement appears too large for the timebox:
1. Split it into the smallest valuable end-to-end slice.
2. Reuse existing product capability first.
3. Prefer proven open standards, licensed components, managed services or partners over reinventing commodity infrastructure.
4. Build only the differentiating layer ourselves.
5. Test the theory before deepening implementation.
6. Bind proof to exact source/image identity.
7. Review the result immediately and improve it again.
8. Repeat continuously.

## 24-hour target product
One integrated manufacturing operating system with a shared semantic model spanning:
- workforce and skills
- attendance, scheduling, absence, overtime and agency labour
- sites, lines, assets and maintenance
- products, parts, BOMs, drawings and manufacturing documents
- production orders and process constraints
- energy, cost and financial outcomes
- decisions, actions and observed results

## Parallel streams

### A. Manufacturing intelligence
- Canonical Factory Graph kernel
- source provenance and temporal facts
- document/BOM/drawing ingestion contracts
- revision lineage
- part/document similarity abstraction
- evidence-backed search and AI retrieval

### B. WFM depth
- time and attendance
- complex rules/premiums
- skills/certification constraints
- absence and leave
- production-driven scheduling
- agency labour
- payroll-grade reconciliation
- worker/manager experiences

### C. Maintenance
- asset hierarchy
- corrective and preventive work orders
- inspections/checklists
- meters and condition signals
- parts/spares readiness
- downtime/failure history
- technician eligibility from skills/certifications
- labour and contractor cost
- production impact and maintenance scheduling

### D. Cross-domain optimisation
- detect production risk
- calculate workforce/maintenance/energy alternatives
- simulate cost and operational consequences
- recommend safest/highest-value action
- require policy/approval where needed
- record actual outcome in Savings/Outcome Ledger

### E. Autonomous implementation and support
- source discovery
- mapping proposal and confidence
- validation/reconciliation
- automated configuration
- generated test pack
- readiness scoring
- drift detection and safe recovery

### F. Product experience
- Vector UI only
- role-first views
- action queue over dashboards
- every metric answers "so what?"
- AI can explain, simulate, report and act within guardrails

## Proof gates
No green status without evidence for:
- exact deployment/source identity
- user journey
- security boundary
- 10,000 employees / 50 sites where applicable
- payroll integrity
- maintenance workflow integrity
- graph provenance
- integration evidence tier
- action policy enforcement
- measurable outcome attribution

## Competitive rule
Do not copy competitor screens. Extract the capability that creates customer value, implement the strongest version that fits our architecture, then test whether our cross-domain model can produce a better outcome.

## Continuous loop
RESEARCH -> GAP -> DESIGN -> THEORY TEST -> BUILD -> INTEGRATE -> TEST -> PROVE -> REVIEW -> IMPROVE -> REPEAT
