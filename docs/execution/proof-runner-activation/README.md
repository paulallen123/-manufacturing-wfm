## Reproduce preparation

From a checkout whose six canonical source files match the verified hashes:

```sh
node docs/execution/proof-runner-activation/prepare.cjs .
node --test docs/execution/proof-runner-activation/launcher.test.cjs docs/execution/proof-runner-activation/preflight.test.cjs
node --test scripts/current-candidate-role-browser-proof.environment.test.mjs docs/execution/proof-runner-activation/source-binding.test.cjs
```

The generator validates the six exact source hashes and produces `generated/start-command.txt`, `generated/bundle.json` and `generated/manifest.json`. The shell-quoted command embeds compressed, hash-bound source and no credentials. It materializes files into a private unique directory only after successful preflight.

Before materialization, npm installation, signer-module loading or child-server startup, the launcher makes one unauthenticated GET to `/api/runtime-identity`. It sends no cookie, authorization header or signer data. Redirects are rejected; the complete fetch and streamed body share a five-second deadline and an 8 KiB maximum. HTTP failure, wrong content type, bad JSON, timeout, redirected response, excess size or stream failure stops startup.

The response must match the configured target SHA exactly, `sourceBinding: "build-file-matched"`, `fixtureOnly: true`, `productionApproved: false` and `pilotReady: false`. The target is never replaced with the returned SHA. This early check only establishes a prerequisite; it does not replace later canonical proof or make a readiness claim.

After preflight, installation remains pinned to Playwright 1.63.0, with scripts disabled and a 120-second forced-termination budget. The installer receives a minimal environment for executable paths, home/temp, locale, trusted CA and proxy transport; it receives no proof signer, actors, customer bindings, provider credentials or `NODE_OPTIONS`. Its cache is deleted before the dependency/source tree becomes read-only. The proof child receives a separate frozen allowlist: explicit signed profile/capability/actor/source/deployment/tenant/run/configuration and strict asset/action bindings, `PORT`, `PLAYWRIGHT_BROWSERS_PATH`, the bounded capability expiry and transport settings. It runs as UID/GID 65534 with a dedicated writable home and excludes unrelated provider/implementation authority, password/passkey inputs, obsolete inline proof scripts, `NODE_OPTIONS`, `NODE_PATH`, dynamic-loader inputs and unknown variables.

The browser launch has a third explicit environment boundary. Chromium receives only string-valued `PATH`, `HOME`, `TMPDIR`, `TMP`, `TEMP`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TZ`, `SSL_CERT_FILE`, `SSL_CERT_DIR`, uppercase/lowercase `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY`. It receives no signer, password, actor/tenant/run/source/configuration or asset bindings, Node/loader hooks, provider/worker credentials or unknown variables. The proof Node process receives only the bounded broker capability; the Ed25519 private key stays in the different-UID launcher parent. Environment projection alone is not the isolation claim: different UID/GID, root-owned read-only code, capability expiry and the hard child deadline form that boundary. Temporary package/source files are restored for trusted cleanup and removed on completion or failure. Live registry/image compatibility remains unverified by this local preparation.
