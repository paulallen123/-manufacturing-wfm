# VECTOR FORGE — Experience Evolution System

## Purpose

VECTOR FORGE is the end-of-week convergence development for VECTOR.

**Tagline:** Forge every capability into one coherent, intelligent manufacturing experience.

The goal is not to add more screens. The goal is to make every new capability improve a real user decision, remove manual work, reduce cognitive load, and strengthen confidence in the product.

## The UX review model

Every existing and new capability is reviewed through the same ten-step loop:

1. **Observe current**
   - capture the real hosted screen;
   - identify what data is visible;
   - identify what actions are actually connected;
   - record loading, empty, error and mobile states.

2. **Map the user job**
   - employee: what do I need to know or do?
   - manager: what needs my decision now?
   - operations: where is production at risk?
   - finance: what is the cost, variance and realised value?
   - director: where should I intervene?
   - company admin: what needs configuration, governance or rollout?

3. **Measure friction**
   - steps/clicks;
   - repeated data entry;
   - duplicated screens;
   - unclear terminology;
   - navigation depth;
   - time to decision;
   - context switching;
   - missing evidence;
   - dead ends.

4. **Design the enhancement**
   - preserve Today / People / Plan / Factory / Improve;
   - bring the decision to the user rather than force navigation;
   - surface the minimum information required to decide;
   - use progressive disclosure for detail;
   - show provenance and confidence where it matters;
   - make graphs actionable, not decorative.

5. **Prototype inside canonical VECTOR**
   - no competing shell;
   - no parallel architecture;
   - no retired/green UI;
   - every prototype uses the blue-and-white VECTOR design system.

6. **Connect real data**
   - no invented values;
   - metrics must state source/recency where important;
   - unknown data must render as unknown;
   - user actions must write authoritative state through the real backend.

7. **Test the complete role journey**
   - desktop;
   - mobile/tablet;
   - role and tenant isolation;
   - refresh/new login;
   - restart where durable state matters;
   - accessibility and keyboard;
   - slow/error/empty states.

8. **Compare before vs after**
   - fewer steps;
   - lower time-to-decision;
   - clearer priority;
   - fewer duplicate surfaces;
   - stronger evidence;
   - more automation without weaker controls.

9. **Simplify**
   - remove redundant cards, tabs and terminology;
   - combine related actions;
   - collapse complexity until the primary user task is obvious.

10. **Evolve**
   - review proof, failures and usage;
   - feed the result into the Digital Twin / learning / support loops;
   - repeat only where measurable value remains.

## Experience architecture

### Today
Purpose: **What needs my attention right now?**

Should evolve into:
- live KPIs;
- highest-impact priorities;
- production/capacity graph;
- exceptions and upcoming risk;
- one-click movement into the exact workflow;
- role-specific emphasis rather than a universal dashboard.

### People
Purpose: **Do we have the right people, skills and availability?**

Should evolve into:
- employee/skills/availability twin;
- attendance and absence;
- leave entitlement/self-service;
- agency readiness;
- competence expiry;
- role-specific actions and development/training prompts.

### Plan
Purpose: **What should happen next?**

Should evolve into:
- genuinely distinct Shift Plan, Shift Patterns, Demand and Cover experiences;
- demand vs capacity;
- skills-constrained allocation;
- overtime/agency/cross-site options;
- simulation before publication;
- cost and compliance consequences before committing.

### Factory
Purpose: **Can we deliver production safely and efficiently?**

Should evolve into:
- Live Factory;
- Site Performance;
- What-if / Simulation;
- Shutdowns;
- line digital twins;
- production risk;
- labour/skills/cost constraints;
- Autopilot recommendations with authority gates.

### Improve
Purpose: **Where is value being created or lost?**

Should evolve into genuinely distinct:
- Performance;
- Cost & Productivity;
- Opportunities;
- Benchmarks;
- Compliance.

The future simplified Cost & Value version should express financial outcomes as:
**Saved → Avoided → At risk → Opportunity → Evidence**

No saving is presented as realised until attributable actual payroll/cost and production outcome evidence supports it.

## Review rules for every FORGE capability

A capability is not considered UX-complete merely because a route or card exists.

It must answer:
1. Who is this for?
2. What decision/action does it improve?
3. What data proves the recommendation?
4. What happens when data is missing or stale?
5. Can the user complete the task from here?
6. Does this duplicate another screen?
7. Does it adapt to role, scope and device?
8. What measurable improvement does the new version create?
9. What can now be removed or simplified?
10. What is the next evolution once actual usage evidence exists?

## Role-lens review

### Employee
Target experience: self-service, obvious entitlement/status, minimal admin, clear next action.

### Manager
Target experience: weekly sign-off, exceptions, cost/efficiency, staffing risk and decisions in one flow.

### Operations
Target experience: production demand → people/skills → allocation → intervention → output.

### Finance
Target experience: labour cost → variance → actual outcome → attributable value → audit evidence.

### Director / executive
Target experience: sites at risk, financial impact, intervention choices and trend/outcome evidence without operational clutter.

### Company admin
Target experience: implementation, integrations, policy, permissions, rollout, health and support with safe defaults.

## FORGE UX gates

Before a capability can be promoted:
- no duplicate rendered experience unless intentionally shared;
- real hosted screen captured;
- action wired to real state;
- data provenance checked;
- mobile/tablet behaviour checked;
- role/tenant boundaries checked;
- empty/loading/error states checked;
- no uncaught browser error;
- comparison against the previous experience documented;
- simplification pass completed.

## Evolution loop after Friday

**OBSERVE → PRIORITISE → REDESIGN → CONNECT → PROVE → MEASURE → SIMPLIFY → EVOLVE**

The first post-FORGE evolution should focus on the simplified **Cost & Value experience**, because the underlying realised-value system can become much richer without making the interface more complicated.
